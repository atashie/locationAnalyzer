# A question the reader must decode is a question they cannot answer

The owner, 2026-11-23: *"We do not communicate well with each other. Please try using
plain-english / simple-english when communicating, and (succinctly) contextualize each ask."*

This is the third time the owner has corrected how reports are written. The earlier two are
recorded in the memory store as `feedback-reply-style`:

* 2026-11-16: plain English, bullets, and next steps split into mine against theirs.
* 2026-11-17: number every ask, because they reply by number.

The numbering was adopted and the split was adopted. The prose was not fixed, and a third
correction followed.

## What was wrong

Two habits, both of which push work onto the reader.

**Names only this project knows.** A single report used *ledger instance 63*, *destination plane*,
*cell-answers*, *the residue*, *default_on*, *ask 7*, *ask 9a* and *the 11-18 decision*, none of
them explained. Each one is a real thing with a real file behind it. None of them means anything to
somebody who has not read the note that coined it. The reader is made to look things up before
they can read the sentence.

**Asks stripped of their context.** The asks were numbered and listed at the end. By then the
reason for each one was several hundred words above it, so answering ask 13 meant scrolling back
to find out what ask 13 was about. Numbering made the reply easier to write and did nothing to make
the question easier to answer.

## The rule

Run reports through the `plain-english` skill, or `simple-english` for anything that reads as
documentation. Never both on one text: they conflict by design.

Every ask must stand on its own and must carry three things:

1. What is being asked, in one sentence.
2. Why it matters, in one sentence: what goes wrong if it is left alone.
3. What I recommend, and why.

An ask must be answerable without scrolling. An ask that only makes sense after reading the
section above it is not finished.

Any term this project invented gets a plain gloss the first time it appears in a report, or it does
not appear. *The layer does not record which shop it measured to* is the sentence. *No destination
plane* is the shorthand, and the shorthand belongs in the code and the notes, not in a report to
the owner.

## How to check before sending

Read the asks alone, in order, with the rest of the message hidden. If an ask cannot be answered
from its own text, it is not written yet.
